# 08 决策记录

## 目的

保留“为什么这样、为什么不那样”，避免重复讨论，也避免把被否方案重新提出来。

## 结论

### D1 u128 → u64（looper 路径）

- **决策**：looper / `stream_states_co` 的状态改为原生 u64，u128 退役。
- **理由**：u128 是类类型，每次位运算是一次 constexpr 函数调用 + 新对象构造；u64 走整数快速路径。
- **被否**：继续用 u128 只“优化位布局”。位不够只是表象，求值器成本才是量级问题。

### D2 不用 fold / `index_sequence` 驱动

- **决策**：类型级进程用递归 + 分块，不改成 pack 展开。
- **理由**：`meta_aligned_iterator` 的推进依赖“上一步的类型”（状态是类型），fold 只线程值；
  `index_sequence` 只给下标不给状态。仓库规则也禁止用它遍历。
- **被否**：把 looper 改写成 fold。对纯类型计算成立，对“每轮类型变化”的进程不成立。

### D3 chunk 是进程续跑点，不是列表切片

- **决策**：chunk 携带完整状态元组，边界必须满足五条不变量。
- **理由**：`index_sequence_istream` 的状态是 `index_counter<N>` 这个进程；按切片处理会丢全局位置。
- **被否**：把 chunk 当作“取下一段元素”。

### D4 payload 重建不能释放内存

- **决策**：不在 chunk 边界“取 payload → `meta_set` 重塞”上做优化。
- **理由**：`meta_set<OBJ>` 得到 `meta_object<OBJ, F>`；参数相同即**同一类型**，编译器已去重。
  内存大头是 payload 自身形态（平表 O(N²)），与是否重建对象无关。
- **被否**：认为重建对象能让编译器回收旧递归树。编译器不回收实例化。

### D5 门位改正向，`G_NOT_SKIP` → `OBS`

- **决策**：8 个门位全部正向；`OBS` 控制“可观察”。
- **理由**：`G_NOT_SKIP` 是负向位；且 `OBS` 与 `REC` 必须正交，否则 `exactly_at`（静默接收、
  只在第 I 轮回调）无法表达。
- **被否**：删掉 `G_NOT_SKIP` 只留 `REC`。

### D6 `POS` 放进 looper word（u32），不进类型参数

- **决策**：`POS` 是 looper word 的 u32 字段；`index_of` 从 looper word 读。
- **理由**：用户明确要求占位放字；掩码可复原越权写入；u32 同时消除 u16 溢出。
- **被否**：`POS` 作为 `integral_constant<size_t, I>` 类型参数。

### D7 计时器：计数进字，target 用类型

- **决策**：`T0C/T1C` 是 looper word 的 u8 计数；压制目标用类型携带。
- **理由**：计数必须跨 chunk 存活（进字）；target 只在装表时决定，做成类型不占位。

### D8 `ACK` 与请求共用 `MAIL`

- **决策**：请求与回执同槽，`FAMILY==ACK` 表示回执。
- **理由**：指令只发一次，覆盖不丢信息；不需要所有权位。
- **被否**：单独的 8 位 ACK 区（挤占 `USER`）、双槽、可变长帧。

### D9 `communicate` + `Fuel=2`

- **决策**：每窗口内最多两轮握手；收敛失败 `static_assert`。
- **理由**：允许“看到回执再修正一次”，同时把实例化深度封顶。
- **被否**：回执晚一轮（v1）；无限往返。

### D10 `flags_operator<u64>` 不提供 `.high`

- **决策**：u64 载体没有 `high`。
- **理由**：提供 `high` 会掩盖“误用 128 位”的代码；缺失时编译失败是想要的行为。

### D11 重构期不跑全量 smoke

- **决策**：只用 `test/` 下的独立用例验收。
- **理由**：smoke 里大量深流用例耗时数分钟；重构期需要快速反馈。

### D12 门位脉冲重建，不继承上一轮

- **决策**：每轮/每窗口由指令重建门位。
- **理由**：粘性门位（清一次就一直清）是旧设计的坑；`FINISH` 的一次性也由此消失。

### D13 组合需求用专用 opcode

- **决策**：新增 `GATES_ARM` 这类指令，牺牲操作数范围，不扩宽 `MAIL`。
- **理由**：信箱宽度固定，ISA 只增不改；范围约束 `static_assert`。

### D14 跨函数边界只传 u64

- **决策**：`communicate` 返回用户最终请求字（u64），`apply` 返回新 looper 字（u64）；
  不使用 `std::pair`，也不使用 `exchange` 之类的两字段结构体。
- **理由**：两字段结构体在常量求值器里和 u128 同类——构造 + 字段访问 + 传值都是对象语义，
  实测 u128 比纯 u64 慢一个数量级。looper 的一轮必须保持纯 u64。
- **被否**：`std::pair<u64,u64>`、`exchange { u64 looper; u64 user; }`、`apply_result` 结构体。

### D15 解码器不模板化

- **决策**：`decoded` 是一个普通结构体，`decode` / `valid` 是 `consteval` 函数。
- **理由**：`decode<Family, Arg>` 会为每条指令实例化一个类型，正是“每条指令一个类型”的
  浪费；校验改用 `static_assert(isa::valid(f, a))`，仍然是编译期错误。

### D16 取值用掩码，不用 `?:` / `if-else`

- **决策**：`select8` / `select64` / `mask8` / `mask64` 做值混合；饱和递减用 `c - (c != 0)`。
- **理由**：AGENTS 规则 2 要求“位运算 / 常量掩码优先”；`if constexpr` 只保留给
  **类型分派**（`drop_mask` 里按 `Obj` 的类别）和**控制流**（ACK / 重复 / Fuel），
  不再用于选值。

### D17 `<bit>` 评估过，热点路径上不采用

- **评估**：`countr_zero` 替代 select 链（原因码、计时器槽）确实让代码更清楚，
  512 轮实测 +0.9s、-8 MiB；但交替重复测量后这 8 MiB 消失（385 vs 386 MiB），
  时间反而略慢。
- **决策**：热点路径保持纯掩码；`<bit>` 仍是允许的依赖（C++20、constexpr、非私有内建），
  以后在非热点处可以直接用。
- **保留**：`select8/select64`、`mask8/mask64` 与打包 `decode`。

### D18 bisect：握手内部保留 apply，不折叠 ACK 表达式

512 轮、`-fsyntax-only`、两次取最小值（RSS 稳定到 ±8 MiB）：

| 变体 | 内容 | maxRSS | 时间 |
|---|---|---|---|
| v0 | zero-apply + 折叠 ACK + `<bit>` + XOR | 427.3 MiB | 3.91s |
| v1 | v0 − `<bit>` | 427.0 MiB | 3.28s |
| v2 | v1 − 折叠 ACK | 424.4 MiB | 2.96s |
| v3 | v2 − zero-apply（恢复内部 apply） | 386.1 MiB | 3.19s |
| v5 | v3 + `<bit>` | 386.2 MiB（重复测量） | 3.16–4.13s |
| **v4** | **v3 − XOR（采用）** | **385.5 MiB** | **2.66–3.43s** |

- **内存主因是“握手内部不 apply”**（+38 MiB）：为了回执里的计时器状态，内部本来就要算一次；
  把它删掉后，`communicate` 用未变更的 L 递归，实例化链变长。
- 折叠 ACK 表达式（把中间量并进一个表达式）多 3 MiB，已回退为具名局部量。
- `<bit>` 首次测到“省 8 MiB”，交替重复后与 v4 相同（386.2 vs 385.5）——那是噪声，
  不是真实收益。
- XOR 字段写入同样在噪声内（±0.5 MiB）。
- 结论：**采用 v4**（无 `<bit>`、无 XOR），它与 v5 内存等同而少一层抽象；`<bit>`
  仍允许在非热点处使用（见 D17）。

### D19 度量标准：只算编译期求值

- **决策**：本重构的所有性能指标只看**编译期**——实例化数、模板深度、求值时间、编译器 RSS。
  **运行期开销不作为度量标准**，也不作为否决理由。
- **理由**：这套东西的产物是常量：`type_safe_aligned_range` 是常量偏移 + 指针，
  `meta_aligned_iterator` 推进是 `base + const`，运行时本来就没有循环、没有分支需要优化。
  looper 在运行期的价值已经兑现，不需要在这里再“省指令”。
- **推论**：
  - 某一轮多算几次 `apply`/`decode` 不构成问题（全在常量求值器里），只要能省编译期内存；
  - 反过来，任何把逻辑泄漏到运行期的改动（真循环、真分支）都是缺陷，而不是“优化”；
  - 基准只用 `-fsyntax-only` + RSS + 实例化数；运行期基准只用来验证“没有泄漏”，不用来比设计。
